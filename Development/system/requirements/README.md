# Requirements

[Use-case flows](use-cases.md) → [system requirements](system-requirements.md) (each with its test and pass criterion).

A requirement states an outcome that is testable on the finished device with the equipment listed
in the [system requirements](system-requirements.md). Internal mechanisms, interface contracts and
implementation parameters belong to architecture and design.

Requirement IDs are stable: an edited requirement keeps its ID, and an ID is not reused. Each
requirement has an anchor of the form `system-requirements.md#req-09`.
