Current workflow · design snapshot

Wi-Fi setup and recovery

Boot, setup, connection and recovery. The diagrams use the same rules as this overview. Target verification remains separate.

01 · Boot or manual setup

Read credentials in L1. At boot, join a saved network with 4 attempts total, 5 s between failures. Confirm the selected network and assigned address. Exhaustion shows an error and waits for a 2 s hold in Idle.

No credentials or a 2 s hold in Idle starts setup. A later hold can re-enter after an exit and can run even while a Wi-Fi error indication is latched.

↓ scan/cache → open AP → serve portal

02 · Prepare the list and open setup

Initial scan first: cache available networks before opening the access point (AP) and serving the portal. Scan has 4 attempts total, 5 s between failures. After exhaustion, show the error; a 2 s hold in Idle restarts setup. AP-start failure also uses manual retry.

The hotspot has no password. The phone joins it manually; a QR (quick response) code opens the portal address. Manual phone rejoin is accepted.

Rescan explicitly or after a failed portal join, keeping AP/server open. Publish the new list only after scan-finished.

03 · Select and connect

One HTML document with changing views. Show the password field only for a protected selected network. Form Back/Cancel returns to selection. On Connect, queue one join attempt; the browser polls status. Keep AP/server available and confirm the selected network and its address, not a previous connection.

No user cancel after Connect submission through join, save and automatic closure. Join failure shows the error, rescans and returns to selection.

04 · Save, show result, close setup

Save through wifi_storeSettings() only after the verified join. Retry saving once: 2 attempts total. If both fail, stay connected with unsaved credentials, preserve the old valid settings and show the save error.

Show success or save warning for 10 s, stop AP/server and retain the station connection.

Cancel and inactivity

Setup exit

Setup Cancel ends setup; form Back returns to selection. Send the closing notice before stopping AP/server, with no extra 10 s Cancel/timeout delay. Keep an established station; otherwise cancel attempts and stop resource-consuming Wi-Fi services. Exit returns to the parent controller, not device shutdown.

Five minutes without activity

Selection, password input and Rescan reset inactivity. Status polling does not. Pause the timer during operations. After five minutes of inactivity, send the closing notice and tear down setup.

Listening and recovery

Listening takes priority

Setup runs only at boot or Idle. A Start request ends connection attempts and AP/portal work safely before audio starts. Keep an established station association. Serialize teardown against successful join completion; reject late events and finish atomic settings writes safely.

Wi-Fi-only failures do not mute or cancel working audio and permit offline Start. Defer reconnection until Idle. Reconnect with 4 attempts total, 5 s between failures; exhaustion opens setup automatically.

If software detects an error that prevents continuing setup, show/log the cause, release setup resources and continue offline. A later 2 s hold in Idle can retry.

Status and error feedback

Context colour plus counted error code

RGB (red, green, blue) shows context: white device, green Idle, cyan audio, violet Wi-Fi, blue FHIR. Portal is steady violet; scan/join/reconnect breathes violet; connection gives 3 quick violet flashes, then the current controller status.

The red button LED shows counted codes at 2 Hz, with a 2 s pause between groups. In violet: save failure 1 blink, scan failure 2, boot join failure 3, reconnect failure 4, AP-start failure 5. The serial log gives the cause. Short press clears indication only; it does not start setup, and automatic recovery need not wait for acknowledgement.

Wi-Fi credential-save failure retains the connection. Generic device settings errors and other faults follow the catalogue halt/clear rules below; restart-required faults cannot be cleared by short press.

Boundaries

L1 owns wifi_readSettings() and wifi_storeSettings(). L2 and the parent controller own workflow and safe teardown. Time synchronization, secure server transport and Device registration belong to the later FHIR (Fast Healthcare Interoperability Resources) phase.

Design snapshot, not a firmware or standards conformity claim. Operation timeouts, resource limits, teardown timing and retained-radio impact on audio still need implementation and target evidence.
