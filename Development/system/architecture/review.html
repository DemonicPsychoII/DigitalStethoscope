Text description of the selected diagram

The chosen design combines layers, RTOS threads and events. Application selects behavior, Services perform the work, and Zephyr connects to hardware. Separate workers keep audio moving; messages coordinate work. Inputs become commands, the controller owns settings, and workers return results. Alternatives shown are a superloop, where slow tasks delay audio, and AUTOSAR, whose automotive module and generated-glue setup is excessive here. Optional MPU task isolation separates task memory when supported. A/B firmware stores two images chosen at boot for update and rollback; it is separate from task and core layout and is not a selected feature.
