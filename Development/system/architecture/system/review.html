Text description of the selected diagram

The chosen design combines layers, RTOS threads and events. Application orchestrates the work, Services provide hardware adapters and pure C libraries, and Zephyr drivers form the bottom layer. Separate workers keep audio moving; messages coordinate work. Inputs become commands, the controller owns settings, and workers return results. Alternatives shown are a superloop, where slow tasks delay audio, and AUTOSAR, whose automotive module and generated-glue setup is excessive here. Optional MPU task isolation separates task memory when supported. A/B firmware stores two images chosen at boot for update and rollback; it is separate from task and core layout and is not a selected feature.

Current session and error catalogue

Busy blocks Start. Faults follow the current catalogue halt/clear rules; Wi-Fi-only faults preserve functioning audio. Numeric acceptance values remain proposals.

Wi-Fi setup and recovery

Initial scan/cache precedes the open hotspot and portal. Rescans keep setup open. Join is queued and the browser polls; credentials are saved only after the selected network has an address. See the current overview, state and flow diagrams for retries, exits and recovery. Time, secure transport and Device registration belong to later FHIR work.
