Text description of the selected diagram

The architecture combines layers, RTOS threads and events. The application orchestrates the work, services provide hardware adapters and pure C libraries, and Zephyr drivers form the bottom layer. Separate workers keep audio moving; messages coordinate work. Inputs become commands, the controller owns settings, and workers return results. A superloop is not used because it is unsuitable for concurrent audio streaming. AUTOSAR is not used because its setup effort exceeds the device scope. Task isolation through memory-domain protection is optional. A/B firmware is not included.

Session and error transitions

Busy blocks Start during analysis; Start during sending cancels the delivery. Audio faults halt listening immediately; restart-required faults block Start until restart. Wi-Fi-only faults preserve functioning audio.
