# Design parameters

These parameters define the system-level timing, sizing, processing and delivery values.

Owners are the firmware modules in the [module map](interfaces-and-behavior.md#static-dependency-and-module-map). Module-specific parameters are defined in [L2_COMMUNICATION](../COMMUNICATION/parameters.md) (P19, P21-COMMUNICATION, P23), [SNTP](../COMMUNICATION/time-synchronization.md#parameters) (P25), [TLS](../COMMUNICATION/secure-transport.md#parameters) (P26), [server communication](../COMMUNICATION/server-communication.md#parameters) (P27), [FEEDBACK](../FEEDBACK/parameters.md) (P22), [L1_PORTAL](../PORTAL/parameters.md) (P21-PORTAL, P24), [L1_WIFI](../WIFI/parameters.md) (P21-WIFI, P23-WIFI) and [L1_STORAGE server profile](../STORAGE/server-profile.md#parameters) (P28).

| P13 | Delivery timeout / retry | One monotonic 10 s deadline from Stop for all attempts and cancellation; connection setup starts when `L2_CONTROL` submits the finalized job. When Wi-Fi is configured, prerequisites are checked once after finalization without waiting; failure latches `DELIVERY_NOT_POSSIBLE` with no attempt. Up to 4 attempts: per attempt, 3 s connection setup (SNTP, DNS, TCP, TLS and verification) when no reusable verified connection exists, plus 1 s write and receipt, capped by remaining global time minus a 1 s cleanup reserve per pending service (P23). A stale or over-keep-alive socket is replaced without consuming an attempt; a failed setup counts as an attempt. A 2 s retry gap starts after failure or timeout and confirmed resource release (`WIFI_CLEANUP_FAILURE` if release fails); fewer attempts run if the global deadline expires. Retry transient transport errors, timeouts, connection resets, incomplete or lost receipts and HTTP 5xx (except unsupported conditional create) with the identical frozen body and conditional-create identity. Configuration/auth errors, TLS certificate/name/validity failures, HTTP 412, unsupported conditional create and other HTTP non-success statuses are terminal. Latch `DELIVERY_FAILURE` on a terminal outcome or exhausted attempts/deadline; latch `SERVER_CONNECTION_FAILURE` instead if no qualifying clock anchor exists by the deadline. Start during Sending cancels the job with the same two outcomes. | Delivery retries are separate from the Wi-Fi budgets in P23 | L2_COMMUNICATION, L2_CONTROL |
